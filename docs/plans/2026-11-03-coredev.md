# coredev Implementation Plan

> **Historical (done).** Built as the `coredev` plugin, now `corecrew` (0.5.x). Command names `/coredev:...` in this plan are `/corecrew:...` today; the layout changed in 0.5.0 (docs/specs/2026-11-04-project-layout-design.md). The tree wins where it differs.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `corekit` plugin into `coredev`: plugin settings, shared machinery in the plugin, a Core skeleton, wiki/knowledge/standards tooling, the `task` orchestrator (with release and adopt), six agents and five hooks.

**Architecture:** One plugin repo. Shared bash machinery in `scripts/` (copied at runtime into the plugin data folder so git hook shims and Claude always run a current copy). Skills are Markdown procedures that call those scripts with settings passed as arguments. Agents are Markdown files. Hooks are bash scripts wired in `hooks/hooks.json`.

**Tech Stack:** bash 3.2 + BSD utilities (macOS), git, Markdown; Claude Code plugin format (`.claude-plugin/plugin.json`, `skills/`, `agents/`, `hooks/hooks.json`).

**Spec:** docs/specs/2026-11-03-coredev-design.md (read it with this plan; section numbers below are the spec's).

## Global Constraints

- Portable bash: macOS bash 3.2, BSD tools. No `sed -i`, `mapfile`, `${x,,}`, `grep -P`, `declare -A`, `local -n`, no `jq`. Temp file + `mv` for edits. Quote every path (spaces, non-ASCII). `tests/test_portability.sh` must cover every new script directory (`scripts/`, `hooks/`).
- Scripts never overwrite or delete user files; idempotent ones print `created` / `skipped`.
- Everything on disk in English. Talk to the user in their language.
- Commit messages: repo style (`feat: …`, `fix: …`, `test: …`, `docs: …`), English, **no `Co-Authored-By` or `Generated with` lines** (owner's rule). Work on branch `feat/coredev`; never commit to `main`.
- TDD: failing test first, watch it fail, then code. A bug fix starts with a test reproducing it.
- Tests run in a sandbox (`new_sandbox`) and never touch the real `~/Projects/Core`, `~/.config`, `~/.claude` or `~/.ssh`. Env used by scripts and tests: `CORE_DIR`, `COREDEV_TOOLS`, `CLAUDE_PLUGIN_DATA`, `HOME` (hook tests).
- After every task: `bash tests/run.sh` → `ALL TESTS PASSED` and `claude plugin validate .` → no errors.
- Plugin version `0.2.0`; CHANGELOG entry `## 0.2.0 — <date>` newest first, in the same change as the bump.
- Nothing personal in the repo: no standards, no session rules, no `/Users/…` paths, no project names (`tests/test_no_personal.sh`, Task 20).
- Agent files ≤ 60 lines; standards ≤ 120 lines; SKILL.md < 500 lines with detail in `references/`.
- Stop after each phase for the owner's check: tell them in Russian how to check it and what may break.

## Review Focus

1. A `core_dir` with spaces or non-ASCII (`/Users/x/My Projects/Ядро`), or given with `~`, a trailing slash or through a symlink — every script and hook must resolve it to one canonical path (`cd -P`), or guards miss and paths break. Tests in Tasks 3, 4, 17.
2. Work inside a worktree (`<Core>/<p>/code/.claude/worktrees/<w>/`): project detection, `guard-code` and `session-start` must treat it as the same project. Tests in Tasks 15, 17.
3. Hook JSON with escaped characters in paths (`\"`, `\\`, `а`) or extra whitespace and newlines — the parser must return the real path or let the call through, never crash or block everything. Tests in Tasks 15, 17, 18.
4. Adopting a folder whose name is not a valid project name, which has uncommitted changes, which is already inside Core, or whose target already exists — refuse with a plain message, change nothing. Tests in Task 13.
5. A Core created by 0.1.x (has `bin/`, `hooks/`, no `.coredev`) — setup must add only what is missing and leave `bin/`/`hooks/` untouched; old git hooks are detected and replaced by shims only through install-hooks. Tests in Tasks 4, 5.
