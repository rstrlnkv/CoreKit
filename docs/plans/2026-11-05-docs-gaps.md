# Docs gaps

Method: a read-only research agent read the current pages under code.claude.com/docs/en
(manifest-reference, marketplace-reference, components, hooks, skills, sub-agents, plugin-evals,
mods) and ran `claude plugin validate` on all three plugins (Claude Code 2.1.318). Its report is
model output: each item below was re-checked against the repo before a decision.

## Verified correct (no action)

- Manifest fields in all three `plugin.json` files and in `marketplace.json` (`displayName` on entries, `renames`, `userConfig` types `string` and `directory`, `options`, `types`) are documented; `validate` passes for all three.
- `renames` entry `"corekit": "corecrew"` is right: the first release of this plugin was named `corekit` (docs/migration-0.2.md). The agent's doubt was unfounded.
- Skill frontmatter (`description`, `argument-hint`, `disable-model-invocation`), description lengths (170–429 chars, limit 1,536), SKILL.md sizes (96–195 lines, guideline 500), `references/` use.
- Agent frontmatter (`name`, `description`, `model: sonnet`, `tools`, `disallowedTools: Agent`, `maxTurns`) is valid; no field that plugin subagents ignore is used.
- Hook events (SessionStart, PreToolUse, Stop), matchers, `${CLAUDE_PLUGIN_ROOT}` quoting, exit 2 plus stderr to block.
- Settings are read from `CLAUDE_PLUGIN_OPTION_<KEY>`, the documented way.
- `claude plugin eval` does not read `evals/evals.json` as cases (it looks for `evals/**/case.yaml` or `prompt.md` + `graders/`), so there is no collision, and also no use: our evals are in skill-creator format only.

## Fixed in this run

| # | Gap | Fix |
|---|---|---|
| D1 | Plain SessionStart stdout goes to the model, not the person. The one-time "Core not set up" hint was printed that way and a marker recorded it as shown, so a hint nobody read was never repeated. | The hint is now `{"systemMessage": ...}` (person-facing, no model context). Tests: JSON shape, valid JSON with a quote and a backslash in the path. |
| D2 | No minimum Claude Code version anywhere. | README "Requirements": 2.1.271 for corecrew (`userConfig` `options`), 2.1.287 for coremodel (hooks module). No manifest field exists for it. |
| D3 | `<task>` in a skill `description` (angle brackets render as entities in listings). | `[task]`, `[version]`, `[folder]`. |

## Left, with the reason

| # | Item | Decision |
|---|---|---|
| D4 | Agents called "Read-only" have Bash, and `permissionMode` is ignored for plugin subagents, so read-only is a promise in text, not a limit. The bodies say "You never edit project files (logs to a file are fine)"; Bash is needed to run builds and tests. | Keep. The word "Read-only" in `description` means "has no Edit/Write tool". Reword only if a future check shows an agent edited a file. |
| D5 | Trigger phrases in `description` instead of `when_to_use` (new-project, second-opinion). | Keep: it works, tests and evals rest on it; moving it is a style change with a trigger-regression risk and no live eval to measure it. |
| D6 | `${CLAUDE_SKILL_DIR}/../..` in new-standard and task instead of `${CLAUDE_PLUGIN_ROOT}`. | Keep: resolves (checked: every such path exists); tests pin the strings. |
| D7 | Top-level `description` in `hooks/hooks.json` is not a documented key. | Keep: `validate` accepts it; harmless. |
| D8 | `if` rules to narrow hook spawns; `statusMessage` on one-suite; `onFailure: "block"` (v2.1.295+) for guard-secrets. | Skipped. Guards cost 19–47 ms per call; a status text would flash on every Bash call; fail-open is a design decision (docs/specs/2026-11-03-coredev-design.md §14: a hook that cannot parse lets the call through) and `onFailure` would raise the minimum version above 2.1.287. |
| D9 | Unused agent fields (`effort`, `isolation: worktree`, `color`), skill `allowed-tools`, newer hook events. | Skipped; no concrete need. |
| D10 | Directory listing fields (`icon`, support/privacy URLs). | Only for submission to the plugin directory; `validate` warns ICON_MISSING. Add an icon before any submission. |
| D11 | `claude plugin tag`. | Optional; releases use CHANGELOG + version bump. |
| D12 | `plugins/coremodel/.claude-plugin/types/` (gitignored). | Parallel session's path; looks like generated output of the mods "get the types" step. Not touched. |

## Could not confirm (needs a live check on the owner's Mac)

- Whether `stop_hook_active` is in the Stop hook input (stop-remind.sh relies on it; its tests use a fake payload).
- Whether `MultiEdit` is still a current tool name (it stays in the matchers; an unused name in a matcher is harmless).
- Whether a hook payload carries an agent identifier (would allow a real read-only guard for agents).
- That the new `systemMessage` hint is displayed in the terminal and in the desktop app as intended.
- Plugin-eval grader details; worth one trial run of `claude plugin eval` on a new-project case (costs real model calls).
