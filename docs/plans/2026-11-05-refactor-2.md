# CoreKit refactor, second pass

The first pass (2026-11-05-refactor-report.md) covered corecrew only; coremodel and coreopinion
belonged to a parallel session, and the live checks were left to the owner. This pass covers all
three plugins and what they do together.

Acceptance lens for every step: *would a user notice this, and is the notice useful?* The plugins
should show up only where needed.

## Order

1. Baseline: tests, validate, versions.
2. Reference: the current Anthropic docs (plugins, marketplaces, skills, subagents, hooks).
3. Promises: every claim of the READMEs, specs and CHANGELOGs → where it lives → which test.
   Functions and files nothing calls; settings declared but unread.
4. Weak spots: guards, timeouts, races, bad conditions (no git, no Core, read-only data, spaces),
   context the plugins add, hook latency.
5. Fixes, test first.
6. Cleanup of superseded docs, code and names.
7. Versions, CHANGELOGs, this report.

Live checks that need a real Claude Code session are listed at the end for the owner.

## Baseline (2026-11-05)

- `bash tests/run.sh`: ALL TESTS PASSED (3 min); `claude plugin validate .` and both sub-plugins pass.
- Versions: corecrew 0.5.2, coremodel 0.4.11, coreopinion 0.2.0.

## Findings and what was done

Sources: three read-only audits (Anthropic docs; coremodel and coreopinion promises; corecrew dead
code and stale docs), each claim re-checked in the tree before acting.

### Fixed (test first)

| Plugin | Finding | Fix |
|---|---|---|
| coreopinion | The Codex profile let GPT read `prod.env`, `app.env.local` and service-account JSON inside the project (checked with `codex sandbox`); README said they are blocked | Profile widened to the send filter's list; a test runs `codex sandbox` over every secret name where Codex is installed |
| coreopinion | `--skip-git-repo-check` was unreachable: outside a repo every step stopped on the git error | Outside a repo only the user's own text goes, with an empty folder for Codex |
| coremodel | `/coremodel` named the level only (README: "what the chat really runs at") and replied in English in a Russian chat | Names the pair; all command replies follow the prompt's language |
| coremodel | `classic.StopFailure`, `classic.SessionStart`: gating hooks without `.catch` (validate) | `.catch` added; test_coremodel fails on the warning |
| coremodel | Texts: "as CoreEffort did", "checking effort…", "non-composer prompts never touched" (Remote Control is checked), stale type comments, spec version/example | Reworded |
| corecrew | SessionStart matcher lacked `fork` (a source in the hooks docs) | Added |
| corecrew | one-suite: a test command repeated within 10 s waited 10.9 s with nothing running | Grace 3 s, poll 1 s; re-run waits ≤ 3 s |
| corecrew | `tests/run.sh` printed ALL TESTS PASSED when coremodel's suite was skipped | Names skipped files after PASSED |
| corecrew | Dead fallback in stop-remind.sh; two shipped plans without banners; statuses left open; migration-0.3 settings list | Removed / banners / closed / fixed |

### Checked, no change

- Corecrew has almost no dead code: every function, message key, script and fixture has a caller.
- `$.ui.place` (flagged as missing from the published mods reference) is in the shipped typings and the log shows no error.
- Unknown words in `models` are logged and shown in the pane; long prompts keep head and tail; the pane level after Back is right.
- Hooks degrade quietly: no git, no Core, read-only plugin data, broken stdin.

### Left for the owner (decisions)

1. **Move corecrew into `plugins/corecrew/`.** Its marketplace source is `./`, so every install
   copies the whole repo (docs, tests, two other plugins) and validate warns about the root CLAUDE.md.
   Large change (paths in tests, docs, `renames`).
2. **coreopinion `allowed-tools: Bash(codex exec *)`** in the skill frontmatter instead of asking
   users to edit settings: one permission prompt fewer, but the harness's own check of the exact
   command goes; the skill's own "send?" question stays.
3. **Read-only agents** (designer, localizer, security, verifier): the hook input now carries
   `agent_type`, so guard-code could refuse Bash writes for them. Today only their prompt says so.
4. **coremodel type-ahead:** only Fable, Extra high and Max questions put Keep first; the mid-chat
   cost question and suggest-mode questions put the switch first, so Enter typed ahead accepts it.
5. **No Opus fallback** when the classifier picks an excluded model (by spec: the model stays).

### Not verified (needs a live session)

- New here: `/coremodel` reply in Russian in the real app; SessionStart context after `/fork`;
  the classifier's 3 s hedge sleep against the 10 s mods hook limit (log shows 4 timeouts of 8 s
  today, no skipped hooks).
- `claude plugin eval` trigger evals (real model calls): not run.
